## 6. ทิศทางงานออกแบบ

**โจทย์:** ร้านพิซซ่าเตาถ่านขนาดเล็ก ลูกค้าส่วนใหญ่สั่งจากมือถือระหว่างเดินทางกลับบ้าน สิ่งที่ต้องเห็นชัดที่สุดคือ *ราคา* กับ *ปุ่มใส่ตะกร้า*

**สี** — ยืมจากเตาอบและวัตถุดิบจริง ไม่ใช่จานสีเว็บทั่วไป

| ชื่อ | ค่า | ใช้ที่ไหน |
|---|---|---|
| ถ่านดำ | `#171310` | พื้นหลังส่วนหัวและหลังร้าน |
| แป้งดิบ | `#F7F1E4` | พื้นหลังหลัก |
| ไฟเตา | `#E2521A` | ปุ่มหลักและราคาเท่านั้น |
| ใบโหระพา | `#38614A` | สถานะสำเร็จ ป้ายหมวดหมู่ |
| มะเขือเทศสุก | `#B23227` | แจ้งเตือน ของหมด |

ใช้สีส้มไฟเตาจุดเดียวคือปุ่มกับตัวเลขราคา ที่เหลือปล่อยให้เงียบ เพื่อให้สายตาไปหยุดที่การตัดสินใจซื้อ

**ตัวอักษร**
- หัวเรื่อง: `Bai Jamjuree` น้ำหนัก 700 — ตัวอักษรค่อนข้างแคบ ตั้งชื่อเมนูยาว ๆ ได้ในบรรทัดเดียว
- เนื้อหา: `IBM Plex Sans Thai` น้ำหนัก 400/600 — อ่านภาษาไทยขนาดเล็กบนมือถือได้สบายตา
- ราคาใช้ `font-variant-numeric: tabular-nums` ให้ตัวเลขเรียงตรงกันทุกแถว

**หลักการจัดวาง**
- การ์ดเมนูสูงเท่ากันทุกใบ ราคาอยู่มุมล่างซ้ายเสมอ เพื่อให้กวาดสายตาเทียบราคาได้เร็ว
- ตะกร้าบนเดสก์ท็อปเป็นคอลัมน์ติดหน้าจอ (sticky) — ลูกค้าเห็นยอดรวมตลอดโดยไม่ต้องเลื่อน
- บนมือถือย้ายตะกร้าเป็นแถบล่างติดหน้าจอ กดแล้วเลื่อนขึ้นมาเต็มจอ
- ไม่มีอนิเมชันตอนโหลดหน้า มีแค่ตอนกดใส่ตะกร้า (ตัวเลขในไอคอนเด้ง) เพื่อบอกว่าการกดสำเร็จแล้ว

**การเขียนข้อความ**
- ปุ่มบอกสิ่งที่จะเกิดขึ้นจริง: "ใส่ตะกร้า 656 ฿" ไม่ใช่ "ตกลง"
- ตะกร้าว่างเขียนว่า "ยังไม่ได้เลือกอะไร เริ่มจากพิซซ่าสักถาดไหม" แทนคำว่า "ไม่มีข้อมูล"
- ข้อผิดพลาดบอกวิธีแก้: "ยอดขั้นต่ำของโค้ดนี้คือ 500 บาท เพิ่มอีก 84 บาท"

## 7. การเชื่อมต่อ API ของหน้าเว็บ

| การกระทำของผู้ใช้ | เรียก API |
|---|---|
| เปิดหน้าเว็บ | `GET /menu` + `GET /menu/toppings/all` |
| กดหมวดหมู่ | กรองใน JS (ข้อมูลโหลดมาแล้ว ไม่ยิงซ้ำ) |
| กดใส่ตะกร้า | เก็บใน state ฝั่ง client อย่างเดียว |
| กดสั่งซื้อ | `POST /customers` → `POST /orders` |
| หน้าหลังร้านเปิด | `POST /auth/login` → เก็บ token ใน memory |
| ดูคิวออเดอร์ | `GET /orders?status=...` ทุก 15 วินาที |
| กดเปลี่ยนสถานะ | `PATCH /orders/:id/status` |
| กดรับชำระ | `POST /orders/:id/pay` |
