# บันทึกการ Refactor

## ปัญหาของโค้ดเดิม

| ปัญหา | ตัวอย่าง |
|---|---|
| ไฟล์เดียวทำหลายหน้าที่ | `order.routes.js` ยาว 250 บรรทัด มีทั้ง routing, validation, คิดราคา, SQL, ตัดสต๊อก |
| ทดสอบไม่ได้ | จะเทสว่าคิดส่วนลด 10% ถูกไหม ต้องเปิดเซิร์ฟเวอร์ ต่อฐานข้อมูล แล้วยิง HTTP |
| ตัวเลขลอย | `const DELIVERY_FEE = 39` อยู่ใน route, `Math.floor(total / 25)` ฝังอยู่กลางฟังก์ชัน |
| SQL กระจาย | คิวรีอยู่ใน 5 ไฟล์ route จะย้ายไป MySQL ต้องแก้ทุกไฟล์ |
| เงินเป็น float | `unitPrice += Number(price) * qty` สะสมความคลาดเคลื่อนทีละสตางค์ |
| error ไม่มีรูปแบบ | บางที่ `res.status(400).json(...)` บางที่ `Object.assign(new Error(), {status})` |
| ตรวจข้อมูลไม่ครบ | เช็ค `if (!items.length)` แต่ไม่เช็คชนิดข้อมูลอื่น |
| เปลี่ยนสถานะข้ามขั้นได้ | `pending` → `completed` เลยก็ได้ ทั้งที่ไม่ควร |
| ยกเลิกแล้วสต๊อกหาย | ตัดวัตถุดิบตอนสั่ง แต่ไม่คืนตอนยกเลิก |

## โครงสร้างใหม่ — 4 ชั้น

```
HTTP request
     │
     ▼
┌─────────────────────────────────────────────┐
│ routes/        เส้นทาง + สิทธิ์ + ตรวจข้อมูล    │  ไม่มีตรรกะธุรกิจ
├─────────────────────────────────────────────┤
│ controllers/   แปลง HTTP ↔ service           │  ไม่รู้จัก SQL
├─────────────────────────────────────────────┤
│ services/      ตรรกะธุรกิจ + transaction      │  ไม่รู้จัก req/res
├─────────────────────────────────────────────┤
│ repositories/  SQL ทั้งหมด                    │  ไม่รู้จักกฎธุรกิจ
└─────────────────────────────────────────────┘
     │
     ▼
  PostgreSQL
```

**กฎง่าย ๆ:** แต่ละชั้นรู้จักเฉพาะชั้นที่อยู่ใต้ตัวเอง ไม่เคยข้ามชั้นและไม่เคยย้อนขึ้น

## เทียบโค้ดจุดสำคัญ

**เดิม** — ทุกอย่างใน route handler เดียว

```js
router.post('/', asyncHandler(async (req, res) => {
  // ...120 บรรทัด: ตรวจ input, วน SQL หาราคา, คิดส่วนลด,
  // INSERT 4 ตาราง, ตัดสต๊อก, บวกแต้ม ปนกันหมด
}));
```

**ใหม่** — route บอกแค่ว่าใครเรียกได้และต้องส่งอะไรมา

```js
router.post('/', authOptional, validate(createSchema), controller.create);
```

**service อ่านแล้วเห็นลำดับงานทั้งหมดในหน้าจอเดียว**

```js
return withTransaction(async (db) => {
  const pricedItems = await pricing.priceItems(items, db);
  const promotion   = promotion_code ? await findValidPromotion(promotion_code, db) : null;
  const totals      = pricing.calcTotals({ items: pricedItems, promotion, orderType: order_type });
  const order       = await orderRepo.insertOrder({ ... }, db);
  // บันทึกรายการ → ตัดสต๊อก → เปิดบิล → บวกแต้ม
});
```

## สิ่งที่แก้ไปพร้อมกัน

1. **ทศนิยมเงิน** — คิดเป็นสตางค์ (จำนวนเต็ม) แล้วค่อยแปลงกลับ มีเทสยืนยันกรณี 0.1 + 0.2
2. **คืนสต๊อกเมื่อยกเลิก** — เดิมวัตถุดิบหายไปเฉย ๆ
3. **กันเปลี่ยนสถานะข้ามขั้น** — `ALLOWED_TRANSITIONS` กำหนดว่าจากสถานะไหนไปไหนได้บ้าง
4. **ข้อความล็อกอินผิดเหมือนกันทุกกรณี** — เดิมบอกแยกว่า "ไม่พบผู้ใช้" กับ "รหัสผิด" ทำให้เดาได้ว่ามีชื่อนี้ในระบบ
5. **แปลง error ของ PostgreSQL** — `23505` กลายเป็น "ข้อมูลนี้มีอยู่แล้วในระบบ" แทนข้อความภาษาอังกฤษดิบ
6. **`authOptional`** — ลูกค้าสั่งเองได้ แต่ถ้าพนักงานกดให้ ระบบบันทึกว่าใครรับออเดอร์
7. **ตรวจ `.env` ตอนเปิดเครื่อง** — ถ้าลืมตั้ง `JWT_SECRET` จะหยุดทันที ดีกว่าไปพังตอนมีคนใช้งาน
8. **ปิดระบบให้เรียบร้อย** — รอ request ที่ค้างอยู่จบก่อนแล้วค่อยปิด connection pool
9. **ลำดับ route** — ย้าย `/report/summary` และ `/toppings/all` ขึ้นก่อน `/:id` ไม่งั้นถูกอ่านเป็น id
